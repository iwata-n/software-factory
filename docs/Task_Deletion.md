# Webアプリでのタスク削除

カンバンのカードを開き、タスク詳細ドロワー上部の「削除」を押す。
対象名と「削除は取り消せません」の警告を確認し、「削除を確定」を押す。
キャンセルまたは Escape では削除しない。

操作者・管理者が同じ Workspace のタスクを削除できる。閲覧者には削除ボタンを表示しない。
実行や詳細化が進行中の場合は、先に既存の取消操作を利用する。
AIとの会話が処理中の場合は、処理終了後に再試行する。

## APIと保持される履歴

`DELETE /v1/tasks/{task_id}` は論理削除を行い、`task_id` と `deleted_at` を返す。
ブラウザーからの書き込みは既存の認証・Origin・接続元保護を適用する。
重複・同時削除は同じ削除結果を返し、監査イベント `task.delete` は一度だけ記録する。

以下のいずれかが存在する場合は409となり、タスクを変更しない。

- 任意の実行履歴に `QUEUED` / `RUNNING` / `WAITING_EXTERNAL` / `CANCELLING` がある。
- 任意の実行履歴に、期限内の `QUEUED` / `RUNNING` のチャット処理がある。

削除後は通常のタスク・Run一覧から全実行履歴を除外する。
Task/Runの詳細取得、仕様更新、新規実行、チャット開始、旧承認・A2UIによる再開も拒否する。
DBのタスク・仕様・実行・チャットと監査記録は保持する。復元UIは提供しない。
Workspaceの既存ロックとTaskロックで、削除・実行開始・チャット・再開を直列化する。
期限切れチャットの遅延した使用量報告は、既存の計量処理で保持する。

## 検証

`tests/test_task_deletion.py` と `tests/acceptance/test_task_deletion.py` は、使い捨てPostgreSQLで
権限、全Run状態、古いRun、チャット期限境界、履歴保持、冪等性、ロールバック、競合を検証する。

`node --test tests/ui/task_deletion.test.mjs` は、本番で使用する削除コントローラーを
DOMの代用オブジェクトで実行する。確認・キャンセル、Escape、二重送信、拒否理由、
失敗後の再試行、ログアウト後の遅延応答を検証する。実ブラウザーは起動しない。
`tests/test_task_deletion_ui.py` はこのテストに加え、ダイアログのアクセシビリティ属性と
静的アセットの配信を検証する。

実画面での確認は別途必要。スマホ幅でドロワーと確認ダイアログを開き、
キャンセル時にカードが残ること、確定後の即時除外と再読み込み後の非表示を確認する。
APIやDOM代用テストの合格を、実ブラウザーでの合格として扱わない。
